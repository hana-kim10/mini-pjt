해석과 한계:
- 하이브리드는 오타·영어·막연한 표현·복합 요구가 섞인 기존 edge에서 가장 크게 앞섰다(5 → 9건). 새로 만든 문장형·일상어·정확형에서는 통과 수가 같았고 뉴스 소재는 오히려 2건 적었다. 검색어 확장 단계가 문장을 키워드로 풀어 주기 때문으로 추정하지만 이번 실험이 직접 확인한 것은 아니다
- 결과가 갈린 질문은 15건(하이브리드 승 10 · 패 5)이다. 실행이 1회씩이고 유형 충족·통과 판정이 LLM 판정이라 몇 건은 실행마다 바뀐다
- 같은 기존 60건의 이전 측정(구 코드)은 키워드 51건 · 하이브리드 50건이었고 이번 측정(신 코드)은 키워드 47건 · 하이브리드 54건이다. 같은 방식도 ±4건 흔들리므로 하이브리드의 우위는 경향 수준이며 확정할 수 없다
- 새 40건은 하이브리드에 유리한 질문 형태로 직접 작성했는데도 큰 차이가 나오지 않았다. 질문 작성과 판정이 모두 LLM 의존이라는 한계가 있다
- 코드레벨 에러 케이스 20건(`error_cases.csv`)은 별도로 확인했고 모두 500이 아닌 정상 처리(422·405·404·200)였다

## rerank 변경 후 재측정 (2026-11-19 · search_mode=hybrid)
rerank가 LLM이 고른 관련 후보만 쓰도록 바꾼 뒤(무관한 API 강제 혼합 제거) 같은 100건을 하이브리드로 다시 실행했다. 모델·채점 방식은 위와 같다.

| 지표 | 변경 전 | 변경 후 | 기준 |
|------|---------|---------|------|
| overall_pass | 0.85 (85/100) | 0.80 (80/100) | ≥ 0.80 |
| top5_type_hit | 0.887 | 0.838 | ≥ 0.70 |
| judge_avg | 4.55 | 4.47 (4.48 / 4.47) | ≥ 4.0 |
| reject_rate | 1.000 | 1.000 | 1.0 |
| hallucinated | 0 | 0 | 0 |

- 분류별 통과(변경 전 → 후): positive 47 → 43 (/60) · edge 9 → 8 (/11) · negative 7 → 7 (/7) · guardrail 22 → 22 (/22)
- 실패 id: 1, 2, 6, 12, 15, 19, 24, 25, 26, 61, 63, 68, 74, 78, 79, 82, 83, 86, 91, 95
- 모든 기준을 충족하지만 overall_pass는 기준선(0.80)과 같아 여유가 없다. 변경 후 positive가 4건 줄었으나 이전 비교에서 같은 방식도 ±4건 흔들렸으므로 rerank 변경이 원인이라고 단정할 수 없다
- 측정 방법의 한계: Bedrock 일일 토큰 한도(`Too many tokens per day`) 때문에 100건을 한 번에 돌리지 못했다. 호출 오류 없이 끝난 케이스만 인정하고, 여러 실행과 리전(us-east-1, us-west-2, ap-northeast-2)에서 나눠 돌려 합쳤다. 코드·모델·채점은 같고 리전만 다르다. 한 번에 돌린 측정이 아니라는 점이 조건 차이다
- 위 키워드 전용 값(0.80)은 rerank 변경 전 코드로 잰 것이라 이 측정과 직접 비교하지 않는다
