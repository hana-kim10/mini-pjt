## 실행 환경
- 모델: Amazon Bedrock Claude Sonnet 4.5 (BEDROCK_REGION·BEDROCK_MODEL_ID 설정값, temperature=0)
- 임베딩 / 벡터 DB: 이 절의 아래 표는 벡터 인덱스 없이 측정한 값(search_mode=keyword_only, 포털 전체 103,237건 대상 키워드 검색 + LLM 검색어 확장·재선별)이다. 하이브리드(Titan v2/Chroma) 재측정 결과는 맨 아래 "하이브리드 재측정" 절과 `metrics.json`에 있다
- 실행 일시: 2026-11-18
- 평가 방식: 일회성 스크립트로 test_queries.csv 60건을 run_agent 로 실행. 유형 충족·통과 여부는 LLM 판정(기대 특성 대비), 시나리오 점수는 LLM-as-Judge 1~5점 2회 평균
- RAGAS(context_recall·precision·faithfulness·answer_relevancy): 이번 실행에서는 측정하지 않음

## 하이브리드 재측정 (2026-11-19 · search_mode=hybrid)
벡터 인덱스(Titan Embed v2 + Chroma, 103,237건)를 만들어 에이전트 도구에 연결한 뒤 같은 60건을 다시 실행했다. `metrics.json`은 이 결과다.

| 지표 | 키워드 | 하이브리드 | 기준 |
|------|--------|-----------|------|
| top5_type_hit | 0.842 | 0.792 | ≥ 0.70 |
| hallucinated | 0 | 0 | 0 |
| judge_avg | 4.86 | 4.68 (4.66 / 4.69) | ≥ 4.0 |
| reject_rate | 1.000 | 1.000 | 1.0 |
| overall_pass | 0.85 (51/60) | 0.833 (50/60) | ≥ 0.80 |

- 하이브리드 결과: 50 / 60 통과 (positive 60% (12/20) · edge 82% (9/11) · negative 100% (7/7) · guardrail 100% (22/22))
- 모든 기준을 충족하지만 키워드 검색보다 나아졌다는 증거는 없다. 수치 차이(51건 대 50건)는 LLM 판정의 변동(±1~2건) 범위 안이다
- 판정 방식 차이: 평가 스크립트가 일회성이라 이전 판정 프롬프트와 같지 않을 수 있다. 시나리오 점수는 독립 호출 2회를 온도 0.3으로 매겼다(이전 측정은 두 번 모두 4.86)
- 실패 id: 1, 2, 6, 9, 11, 12, 15, 17, 25, 26 (이전 키워드 실패 id: 1, 2, 6, 9, 16, 24, 25, 28, 29)
- 눈에 띄는 실패: #2 입력 가드가 정상 질문을 거절(이전과 같음), #11 세탁업 지자체 사본이 상위에 연속 노출(사본 묶기 누락), #25 오타 질의에서 기대한 표준데이터 누락
- 위 하이브리드 수치는 아래 입력 가드 수정 전 코드로 측정했다. 수정 후 60건 전체 재평가는 하지 않았다(Bedrock 일일 토큰 한도 `Too many tokens per day`로 호출이 막혀 한 번의 재평가가 오염되어 폐기함)
- 입력 가드 수정: (1) LLM 검사 프롬프트에 "창업·개원·개업처럼 하려는 일을 밝히는 문장은 정상"을 명시해 #2 오탐을 줄임(가드만 60건에 2회 돌려 정상 질문 오탐 0건, #2 문장 5회 모두 통과), (2) LLM 검사가 실패하면 통과시키지 않고 차단하며 별도 안내문("일시적인 오류…")을 돌려주고 감사 로그에 `guard_error`로 구분 기록함(fail-closed)
- RAGAS는 이번에도 측정하지 않았다
